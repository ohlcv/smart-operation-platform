## 一、项目背景

甲方为文旅行业企业，旗下管理多个景区/业务点，涉及多渠道售票（OTA、抖音等平台）、资金往来、发票管理、多层级审批、客户资信管理等多项经营活动。目前相关业务分散在人工对账、线下审批、独立表格统计中，缺乏统一的数字化管理平台，导致数据滞后、对账繁琐、审批效率低、经营决策缺乏数据支撑。

本项目旨在搭建一套**智慧文旅经营管理平台**，实现"业务数据可视化 + 财务资金一体化 + 审批流程线上化 + AI辅助决策"，服务于公司管理层、业务部门、财务部门等多角色。

---

## 二、产品目标

1. 为管理层提供一个全局可视化驾驶舱，实时掌握经营、财务、风险状况。
2. 打通多渠道（OTA、抖音等）业务数据，实现自动对账，减少人工核对成本。
3. 实现资金、发票、审批的线上一体化闭环管理。
4. 引入AI能力，辅助经营诊断、风险预警、资金配置建议、客户投前分析，提升决策效率。
5. 建立标准化、可追溯的企业级审批流程。

---

## 三、目标用户与角色

| 角色 | 使用场景 |
|---|---|
| 公司领导/高层 | 查看战略总览驾驶舱、经营分析仪表盘，做经营决策 |
| 业务经办人员 | 发起业务、上传合同、管理各渠道订单与核销 |
| 业务审核/风控人员 | 审核业务合规性、风险把控 |
| 财务人员（经办/复核） | 管理发票、开票、资金监控、审批财务环节 |
| 部门负责人 | 审批本部门相关业务 |
| 客户对接人员 | 维护客户档案，发起投前调研分析 |

## 四、功能架构总览

系统共分为 **6 大一级模块**：

1. 战略总览驾驶舱
2. 智能化经营数据中心
3. 全渠道业务管理中心
4. 智慧财务管理系统
5. 标准化审批流程中心
6. 全景化客户档案库

```
智慧文旅经营管理平台
├── 一、战略总览驾驶舱
├── 二、智能化经营数据中心
├── 三、全渠道业务管理中心

```

## 五、功能模块详细需求

### 模块一：战略总览驾驶舱

**模块定位**：全局业务动态与核心指标可视化监控中心，面向管理层的"总仪表盘"。

| 功能点 | 需求描述 |
|---|---|
| 全域业务态势图 | 以中国地图为载体，立体化展示各区域业务分布与核心财务表现（如营收、订单量等按区域着色/气泡展示） |
| 智能审批流看板 | 实时跟踪展示各类审批流程的进度、状态（待审批/审批中/已完成/已驳回等） |
| 核心财务指标 | 聚焦营收、利润等关键财务数据，提供趋势图与同比/环比洞察 |
| 实时销售数据监控 | 动态展示各景区销售流水与核销情况 |
| AI智能风险雷达 | 全景式风险监测与预警，自动识别异常经营/资金/审批风险并提示 |

**待确认问题**：
- 地图展示的区域颗粒度（省级/市级/景区级）？
- 风险预警的具体规则和阈值由谁定义？

---

### 模块二：智能化经营数据中心

**模块定位**：经营数据的深度分析与决策支持。

| 功能点 | 需求描述 |
|---|---|
| 多维经营分析仪表盘 | 支持日、月、年等多时间维度统计、对比与波动分析；数据支持在线查看或一键导出至Excel |
| AI智能经营诊断 | 基于业务数据自动进行深度分析、归因解读与趋势预测（如"营收下降原因分析"） |

**待确认问题**：
- AI诊断的输出形式是文字报告、图表，还是两者结合？
- 是否需要支持自定义分析维度？

---

### 模块三：全渠道业务管理中心

**模块定位**：多业务线统筹与精细化运营。

| 功能点 | 需求描述 |
|---|---|
| 业务全景统筹视图 | 支持按业务类型灵活筛选与查看全部业务数据 |
| 多渠道数据融合 | 无缝接入OTA、抖音等平台，自动同步订单、核销及退款数据至总览 |
| 自动化对账管理 | 每个景区以超链接方式直连各销售渠道后台，便捷导出核销数据并回传，系统自动归集生成标准化核销台账 |

**待确认问题**：
- 具体需要对接的渠道清单（携程、美团、抖音生活服务、飞猪等）？
- 各渠道是否提供开放API，还是需要通过其他方式获取数据（如爬取/手动导出）？
- 对账周期（实时/日结/月结）？

---

### 模块四：智慧财务管理系统

**模块定位**：资金、票据与资产效能一体化管理。

| 功能点 | 需求描述 |
|---|---|
| 资金全景监控 | 直连银行系统，实时洞察客户回款与公司支出动态 |
| 全流程发票管理 | 每月对上传进项发票归集至各项业务中，并根据各项业务的核销数据台账，支持发起开票流程，经部门负责人在线审批，财务经办依审批结果开票，系统支持审批单打印与电子凭证永久留存，实现凭证流闭环 |
| AI资产配置建议 | 智能识别账户闲置资金，结合业务规划，提供科学的资金使用建议 |

**待确认问题**：
- 直连银行系统涉及哪家银行、是否有对公账户API对接资质？
- 发票开具是否需要对接税务系统（如全电发票）？

---

### 模块五：标准化审批流程中心

**模块定位**：企业级全电子化审批工作流。

| 功能点 | 需求描述 |
|---|---|
| 规范审批链 | 支持业务发起、信息录入与合同上传，经业务经办、业务审核、风控审核、财务经办、财务复核、部门负责人及公司领导的全链路逐级审批。审批完结后，系统支持审批单打印与电子凭证永久留存 |

**待确认问题**：
- 审批流程是固定流程还是需要支持可视化配置（不同业务类型走不同审批链）？
- 是否需要支持加签、转办、抄送等常见OA功能？
- 是否需要移动端审批（微信/企业微信/钉钉）？

---

### 模块六：全景化客户档案库

**模块定位**：客户信息管理与智能资信分析。

| 功能点 | 需求描述 |
|---|---|
| 客户主数据档案 | 完整收录客户名称、ID、地址、联系人、电话及全套资质文件（如营业执照、财报、企业实景图等） |
| AI智能投前分析 | 整合客户档案与外部网络资讯，由AI自动生成深度业务调研与可行性分析报告 |

**待确认问题**：
- 外部网络资讯的数据来源（企查查/天眼查类第三方数据接口，还是公开网络搜索）？
- 投前分析报告的格式与审核机制？

## 六、非功能性需求

| 类别 | 需求说明 |
|---|---|
| 权限管理 | 需支持多角色、多层级的权限体系（管理层/业务/财务/风控/部门负责人等） |
| 数据安全 | 涉及银行资金、发票、客户资质等敏感数据，需符合金融/隐私数据安全规范，权限最小化、操作留痕 |
| 系统集成 | 需与银行系统、OTA/抖音等第三方平台、发票/税务系统对接 |
| 可扩展性 | 审批流程、渠道对接需支持后续灵活扩展新业务、新渠道 |
| 性能要求 | 驾驶舱大屏、实时监控类功能需保证数据刷新的及时性（具体指标待定） |
| 操作留痕 | 审批、开票等关键操作需全程留痕，支持审批单打印与电子凭证永久存档 |

## 七、待与甲方确认的关键问题清单

1. 需要对接的OTA/渠道平台具体清单及对接方式（API/人工导出）。
2. 审批流程是否需要支持自定义配置，还是按固定流程开发。
3. 银行直连的具体银行及资质要求。
4. AI相关功能（经营诊断、风险雷达、投前分析、资产配置建议）的技术实现方式：
   - 是否调用大模型（如接入第三方AI能力）？
   - 分析规则/预警阈值由谁提供？
5. 客户资信分析的外部数据来源是否需要采购第三方数据接口（如企查查API）。
6. 是否需要移动端/小程序支持审批与查看驾驶舱。
7. 系统上线节奏：是否分期交付（如先上线财务+审批，再上线AI功能）。
8. 数据历史迁移需求：是否需要导入历史业务/财务数据。
