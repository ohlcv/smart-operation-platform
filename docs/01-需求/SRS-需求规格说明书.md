## 需求规格说明书

> 文档版本：v3.0（整合版）
> 生成日期：2026-07-10
> 文档定位：企业级 B2B 业务管理系统，面向文旅行业的供应链管理与票务代理销售平台；作为开发功能对照文档及技术负责人验收依据。

## 一、项目概述

### 1.1 项目背景

山东出版供应链管理公司业务平台，是面向文旅行业的 **企业级 B2B 业务管理系统**，集供应链管理、合同审批、财务管控、票务代理销售于一体。

**核心业务范围：**

1. **供应链管理** — 景区/文旅档案管理、供应商资质管控
2. **合同审批** — 7 级审批流，支持付款审批单/业务审批单
3. **财务管控** — 进账出账、结算付款、发票管理、银行对账
4. **票务代理** — 对接美团、抖音等 OTA 平台，实现多渠道票务销售与统一管理

**核心业务场景：**

```
┌─────────────────────────────────────────────────────────────────────┐
│                         B2B 票务业务流程                              │
├─────────────────────────────────────────────────────────────────────┤

│        │                                    │                        │
│        │ 结算、发票                         │ 销售、结算              │
│        ◄────────────────────────────────────                        │
│                                                                      │
│   （景区/文旅）──授权票种+密钥──► 出版社──绑定票种+密钥──► 抖音  │
│        │                                    │                        │
│        │ 结算、发票                         │ 销售、结算              │
│        ◄────────────────────────────────────                        │
│                                                                      │

│   1. 合同管理：7 级审批流，合规管控                                   │
```

### 1.2 交付范围

本项目交付包含两个终端：

| 终端 | 技术栈 | 说明 |
|------|--------|------|

## 二、用户角色体系

### 2.1 角色定义（8 级）

系统支持 **8 级角色**，其中审批链为 **7 级**，超级管理员为隐藏系统角色，**不纳入审批链**：

审批链角色按顺序排列如下：

| 序号 | 角色标识 | 角色名称 | 职责说明 | 是否纳入审批链 |
|------|----------|----------|----------|---------------|
| 1 | `business_handler` | 业务经办 | 创建合同、提交审批、管理渠道和客户档案 | 是 |
| 2 | `business_reviewer` | 业务复核 | 业务层面复核 | 是 |
| 3 | `risk_auditor` | 风控审核 | 风险控制审核 | 是 |
| 4 | `finance_handler` | 财务经办 | 财务数据处理、开票 | 是 |
| 5 | `finance_reviewer` | 财务复核 | 财务复核确认 | 是 |
| 6 | `scm_director` | 供管公司负责人 | 供应链管理部门审批 | 是 |
| 7 | `invest_director` | 投资公司负责人 | 最终审批（终审） | 是 |
| 8 | `admin` | 超级管理员 | 系统管理，不受权限限制 | **否（隐藏）** |

**超级管理员（admin）特殊权限说明：**

超级管理员为隐藏角色，不出现在常规审批链中，拥有以下顶级权限：

| 权限类别 | 具体权限 |
|----------|----------|
| 用户与权限 | 创建/编辑/删除任意用户；分配/撤销任意角色 |
| 页面与操作 | 查看所有菜单和页面；执行所有操作（含审批放行） |
| 系统管理 | 系统参数配置、数据字典管理、通知公告发布 |
| 审批特殊权限 | 可审批任意环节（审批链 bypass） |
| 数据管理 | 可查看/导出所有业务数据 |
| 签名管理 | 可重置任意用户的电子签名 |
| 日志审计 | 可查看所有操作日志和登录日志 |

> 说明：超级管理员账号不公开分配，仅在系统维护或紧急审批场景下使用。

### 2.2 角色与功能对应关系

| 角色 | 可见业务模块 |
|------|------------|
| 业务经办 | 合同创建、渠道管理、客户管理、经营数据录入 |
| 业务复核 | 审批中心（业务环节）、合同查询 |
| 风控审核 | 审批中心（风控环节）、合同查询、经营数据查看 |
| 财务经办 | 审批中心（财务环节）、发票管理、财务管理 |
| 财务复核 | 审批中心（财务复核环节）、财务报表 |
| 供管公司负责人 | 审批中心（供管环节）、合同查询 |
| 投资公司负责人 | 审批中心（终审环节）、战略总览 |
| 超级管理员 | **全部模块和页面，无任何限制** |

## 七、技术标准

### 7.1 工业级标准

| 标准类别 | 具体要求 | 实现方式 |
|----------|----------|----------|
| **代码规范** | PEP8（Python）、ESLint+Prettier（前端） | 自动化检查、CI/CD |
| **API 设计** | RESTful 规范、OpenAPI 3.0 文档 | 自动生成接口文档 |
| **安全认证** | JWT Token、基于角色的访问控制 | 细粒度权限控制 |
| **数据安全** | 敏感数据加密存储、SQL 注入防护 | bcrypt 加密、参数化查询 |
| **传输加密** | 前后端数据传输加密 | RSA+AES 混合加密 |
| **XSS 防护** | 输入过滤、输出转义 | DOMPurify + 后端过滤 |
| **CSRF 防护** | Token 验证 | 防 CSRF 攻击 |
| **日志审计** | 操作日志、登录日志 | 完整审计追踪 |
| **接口限流** | 防暴力破解、防 DDoS | Redis 限流、IP 封禁 |
| **异常处理** | 全局异常捕获、统一响应格式 | 中间件统一处理 |

### 7.2 业务合规

| 合规要求 | 说明 |
|----------|------|
| **数据一致性** | 多平台数据统一口径，避免数据冲突 |
| **对账机制** | 支持平台账单与系统记录自动核对 |
| **审批留痕** | 关键操作（结算、付款）需审批通过 |
| **财务合规** | 进账出账有据可查，支持财务审计 |
| **密钥安全** | 平台 API 密钥加密存储，不明文展示 |
