## 一、项目定位与目标

### 1.1 系统定位

山东出版供应链管理公司业务运营平台，是面向文旅行业的 **B2B 企业级业务管理系统**，以 **RuoYi-Vue3-FastAPI** 为技术底座，复用 v1 demo 的科技风 UI 和审批流逻辑，最终实现供应链合同审批、票务渠道集成、财务管控、经营数据分析的一体化管理。

### 1.2 建设目标

| 目标 | 说明 |
|------|------|
| **技术底座** | 基于 RuoYi-FastAPI 框架，使用其用户/角色/菜单/日志等系统管理功能 |
| **核心亮点保留** | v1 demo 的 7 级审批流、科技风 UI、数据大屏、飞线地图、AI 诊断完整迁移 |
| **业务补齐** | 新增 OTA 平台对接、银行对账、发票管理、经营数据等模块 |
| **视觉统一** | 全站覆写为 v1 demo 的科技风深色主题 |

### 1.3 非功能指标

| 维度 | 指标 |
|------|------|
| **性能** | 普通接口响应 < 500ms，页面加载 < 2s，大屏 < 3s |
| **并发** | 支持 50 人同时在线，OTA 同步延迟 < 5 分钟 |
| **可用性** | 系统可用率 > 99.5% |
| **安全** | 等保二级，JWT 无状态认证，按钮级权限控制 |

## 四、安全架构

### 4.1 认证与授权

**JWT 无状态认证：**

```
用户登录 → 验证账号密码 → 生成 JWT Token（含 userId、roles、permissions）
     ↓
请求 API → Authorization: Bearer {token}
     ↓
后端校验 Token → 验证签名 / 有效期 → 解析用户身份
     ↓
通过 DBSessionDependency 注入当前用户
     ↓
通过 UserInterfaceAuthDependency 校验按钮权限（接口级）
     ↓
业务层通过 ApprovalService.can_approve_contract() 做业务级校验
```

### 4.2 7 级审批权限模型

> 详见《权限模型设计.md》第三章

**Step 与角色对照表：**

| Step | 角色标识 | role_key | 角色名称 | 说明 |
|------|----------|----------|----------|------|
| 0 | BUSINESS_HANDLER | business_handler | 业务经办 | 提交人；提交时自动完结，无需他人审批 |
| 1 | BUSINESS_REVIEWER | business_reviewer | 业务复核 | — |
| 2 | RISK_AUDITOR | risk_auditor | 风控审核 | — |
| 3 | FINANCE_HANDLER | finance_handler | 财务经办 | — |
| 4 | FINANCE_REVIEWER | finance_reviewer | 财务复核 | — |
| 5 | SCM_DIRECTOR | scm_director | 供管公司负责人 | — |
| 6 | INVEST_DIRECTOR | invest_director | 投资公司负责人 | 终审，通过后合同生效 |

- 超管（admin）：`role_sort=0`，`role_key=admin`，跳过审批链限制，可审批任意环节
- 同一用户不能在自己提交的合同中担任审批人（边界条件见《权限模型设计.md》§9.2）
- `role_id` 固定取数（详见《数据库设计.md》§5.1）：业务经办=2、业务复核=3、风控=4、财务经办=5、财务复核=6、供管=7、投资=8

### 4.3 数据范围过滤

> 详见《权限模型设计.md》第七章

业务经办的合同列表受 `sys_role.data_scope` 限制（详见《权限模型设计.md》§7.1）：本人创建（data_scope=5）或本部门（data_scope=3）。超管和审批角色不受限制。

### 4.4 安全措施

| 措施 | 实现方式 |
|------|----------|
| 防暴力破解 | Redis 计数，5 次失败锁定 30 分钟 |
| 密码加密 | bcrypt 哈希存储 |
| SQL 注入防护 | SQLAlchemy 参数化查询 |
| XSS 防护 | 前端 DOMPurify + 后端过滤 |
| 渠道密钥加密 | RSA 加密存储 |
| 操作审计 | 登录日志 + 操作日志（沿用 RuoYi） |
| 电子签名（个人） | Base64 data-URI，存储于 `sys_user.signature` |
| 电子签名（审批快照） | 审批通过时复制签名到 `biz_approval.signature_snapshot`，用于存档审计 |
