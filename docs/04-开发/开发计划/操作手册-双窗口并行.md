## 二、本手册原意（为未来归档）

以下保留原始框架，仅作参考。

### 2.1 原始文档定位

> 指导在两个 Cursor 窗口同时开路线 A + 路线 B 的工程师。包含**开局前准备**、**两个窗口的具体任务清单**、**提交与合并流程**。

### 2.2 适用场景（未来）

如果将来项目重启类似「业务闭环 + 大屏可视化」并行任务，**本手册提供现成的 5 步合并框架**：

1. **阶段 0：共用文件合并**（30 分钟）
   - router 一次性注册（避免子路由顺序冲突）
   - enums 占位（避免同时改一个 enum 文件）
   - SQL menu_id 一次性分配（避免菜单插入冲突）
   - controller 自动注册检查（避免重复 import）

2. **阶段 1：双窗口并行**
   - 路线 A 与路线 B 在文件级互斥（每个 .py / .vue / .sql 只属于一条路线）
   - 共用文件只在阶段 0 触碰，阶段 1 期间两边不再触碰

3. **阶段 2：合并**
   - git pull + merge 两条 feature 分支
   - 解决可能的 router / enum 冲突
   - 端到端验收

## 三、原始阶段 0（参考价值）

### 步骤 0.1：路由补齐（5 分钟）

**文件**：`src/router/index.js`

**改动**：在 `/biz` 父路由下追加共用路由。

### 步骤 0.2：枚举预占位（5 分钟）

**文件**：`module_biz/enums.py`

**改动**：占位未来需要的 enum，避免双窗口同时改同一个文件。

### 步骤 0.3：菜单 menu_id 预分配（10 分钟）

**文件**：`sql/biz_menus_roles_init.sql`

**核心规则**：
- 固定分配 menu_id（如 A 拿 9-12，B 拿 13-16）
- **写完整 path**（含父级 `biz/` 前缀，与 contract/customer 风格一致）
- **去掉 `biz:` 前缀**（与 controller `UserInterfaceAuthDependency` 一致）

### 步骤 0.4：controller 自动注册（5 分钟）

**当前实现**：`module_biz/__init__.py` 实际不需要手动注册，由 `common/router.py auto_register_routers` 自动扫描 `module_biz/controller/`。**避免双窗口各自动注册一次导致重复路由**。

### 步骤 0.5：Git 提交（5 分钟）

```bash
git add .
git commit -m "v3.0+: 路由补齐 + 枚举预占位 + 菜单 menu_id 分配（共用文件）"
```

## 五、原始「阶段 1 双窗口并行」参考

如果未来真的需要双窗口并行，**两个窗口的 Git 提交顺序**：

```bash
# 窗口 B 先提交（因为不依赖 SQL/路由之外的共用文件）
git commit -m "v3.0-路线B: ...（战略驾驶舱）"
git push origin feature/route-b

# 窗口 A 后提交（SQL 改动）
git commit -m "v3.0-路线A: ...（业务闭环 4 模块）"
git push origin feature/route-a

# 主窗口合并（按 SQL 改动先后排序）
git checkout main
git merge feature/route-a   # 先 A（SQL 改动大）
git merge feature/route-b  # 后 B（驾驶舱）
```
