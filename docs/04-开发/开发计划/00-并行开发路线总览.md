# 并行开发路线总览（2026-07-11）

> 文档创建日期：2026-07-11
> 文档定位：v2.9 已完成（审批中心全功能）后，将剩余 12 个待办任务拆分为 **两条互不冲突、相互补充** 的并行路线。两个 Cursor 窗口同时开发，文件依赖通过本表对照。
>
> **拆分原则**：
> - **文件不重叠**（每个 .py / .vue / .sql 只能属于一条路线）
> - **路由前缀不同**（避免 router/index.js 冲突）
> - **数据源解耦**（路线 B 的驾驶舱读合同/审批/客户表，路线 A 不依赖驾驶舱；路线 A 的合同/审批也不被驾驶舱写）
> - **DB 表不重叠**（每条路线管自己的表）
> - **共用 enums / router / store / request**：必须 **先合并到主干再开窗口**（由"主导窗口"在开局前一次性同步）

### 共用文件 2：`module_biz/enums.py`

**当前状态**：已有 `ApprovalStepEnum`、`ContractStatusEnum`、`ContractTypeEnum`。

**路线 A 需追加**：
- `ChannelCategoryEnum`（景区门票/酒店数据/综合 OTA/其他）
- `InvoiceStatusEnum`（待开/已开/已作废）
- `FinanceEntryTypeEnum`（应付/应收）
- `OperationPeriodEnum`（月报/季报/年报）

**路线 B 需追加**：无（全部从已完成 VO 推导）。

### 共用文件 3：`sql/biz_menus_roles_init.sql`

**路线 A 追加菜单**（menu_id=9-12）：channel / invoice / finance / operation 4 个菜单 + 角色菜单关联
**路线 B 追加菜单**（menu_id=13）：cockpit + dashboard + profile + system 4 个菜单

**冲突解决**：menu_id 必须互不重复，开局前在主文档里固定分配。

```
9  → 路线 A 渠道管理（channel）
10 → 路线 A 发票管理（invoice）
11 → 路线 A 财务管理（finance）
12 → 路线 A 经营数据（operation）
13 → 路线 B 战略驾驶舱（cockpit）
14 → 路线 B 首页工作台（dashboard）
15 → 路线 B 个人中心（profile）
16 → 路线 B 用户管理（system:user）
```

### 共用文件 4：`module_biz/__init__.py` 自动注册

两个新 controller（路线 A 的 channel/invoice/finance/operation 共 4 个 + 路线 B 的 cockpit 1 个）需要在 `auto_register_routers` 中注册。**新增的 controller 注册语句必须在合并前一次性追加好**，各自窗口不动这个文件。

## 四、开发顺序建议（避免阻塞）

### 阶段 0：合并共用文件（一次性，30 分钟）

主窗口执行：
1. 改 `src/router/index.js`（补全 `contract` / `customer` 子路由）
2. 改 `module_biz/enums.py`（追加 4 个 enum 占位）
3. 改 `sql/biz_menus_roles_init.sql`（按上面分配的 menu_id 追加菜单条目 + 角色权限）
4. 改 `module_biz/__init__.py`（注册 5 个新 controller）

### 阶段 1：两个窗口并行

| 时间 | 窗口 A（业务闭环） | 窗口 B（大屏可视化） |
|------|------------------|--------------------|
| Day 1 | channel 后端 5 文件（11h）| cockpit 后端 3 文件（6h） |
| Day 2 | channel 前端 2 文件（5h）| BaseChart + CountTo 组件（5.5h） |
| Day 3 | invoice 全套（13.5h）| ScreenMap + cockpit 前端（13.5h） |
| Day 4-5 | finance + operation（35h，分 2 天）| dashboard + profile + system（14h） |

### 阶段 2：合并 + 端到端验收

两个窗口都完成后：
1. 拉取最新代码，merge 两个分支
2. 解决可能的 router / enum 冲突
3. 跑端到端验收：
   - 路线 A：完整业务链（合同→审批→渠道→发票→财务→经营）
   - 路线 B：登录→dashboard→cockpit→profile→system 全跑通

## 五、风险与冲突预警

| 风险 | 触发场景 | 缓解措施 |
|------|---------|---------|
| `module_biz/enums.py` 同时被改 | 路线 A 追加 4 个 enum，路线 B 不动 | 阶段 0 先建占位 enum，路线 A 仅填充 |
| `sql/biz_menus_roles_init.sql` menu_id 冲突 | 两边都用同一个 ID | 阶段 0 固定分配（A: 9-12, B: 13-16） |
| `src/router/index.js` 子路由顺序不一致 | 两边都改 children 顺序 | 阶段 0 一次性排好，后续只追加不调整顺序 |
| `module_biz/__init__.py` 重复 import | controller 注册重名 | 阶段 0 一次性注册好，两边不再触碰 |
| 路线 B 的 cockpit 依赖已完成的 contract/approval 表 | 路线 B 启动时已完成模块已稳定 | 已确保 contract/approval 是 v2.9 已完成项，不会被两条路线改动 |
| 路线 A 的菜单分配与 7 级审批角色的菜单冲突 | admin 看不到业务菜单 | 阶段 0 一次性把 admin 角色挂全部菜单 |
| dashboard 路由替换 RuoYi 默认首页 | 替换后 RuoYi 自带的 dashboard.vue 失效 | 路线 B 实施前先备份 RuoYi 原 dashboard.vue，必要时可回退 |
