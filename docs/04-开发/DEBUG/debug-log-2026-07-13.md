## 1. 当前问题

### 现象

打开前端「系统管理 → 角色管理」的「分配用户」按钮，点击报错：

```
[Vue Router] No route matches '/system/role/user/3'.
```

### 根因

**前端链接路径与 router 配置不一致**，是 Vue Router 严格匹配导致的。

| 项目 | 值 |
|---|---|
| 菜单/按钮实际链接 | `/system/role/user/3` |
| router 注册的动态路由 | `/system/role-auth/user/:roleId` |
| 结论 | **路径不匹配**，导致 Vue Router 无法找到对应组件 |

### 修复方案

把菜单/按钮的链接从 `/system/role/user/:roleId` 改为 `/system/role-auth/user/:roleId`，与 `router/index.js` 中定义的 `system:role-auth` 动态路由对齐。

## 2. 本次排查 & 修复历程

### 2.1 阶段一：Swagger/ReDoc 无法访问

**时间**: 07:32  
**现象**: Docker 容器启动后，访问 `/tool/swagger` 或 `/proxy-docs` 报错，`.env.dockermy` 中 `APP_DISABLE_SWAGGER=true` 和 `APP_DISABLE_REDOC=true` 被关闭了文档路由。

**排查过程**:
1. 检查 `ruoyi-fastapi-backend/.env.dockermy` 第 25、27 行
2. 发现 `APP_DISABLE_SWAGGER = true`，`APP_DISABLE_REDOC = true`
3. 框架代码中这两个 flag 为 true 时会跳过 `app.include_router(swagger_ui)` 和 `app.include_router(redoc)`
4. `/proxy-docs` 路由未注册，导致 Nginx 转发到后端 404

**修复**: 改回开发默认值

```diff
- APP_DISABLE_SWAGGER = true
- APP_DISABLE_REDOC = true
+ APP_DISABLE_SWAGGER = false
+ APP_DISABLE_REDOC = false
```

### 2.2 阶段二：宿主机缓存污染 Docker 镜像

**时间**: 07:33  
**现象**: 虽然 `.env.dockermy` 已修复，但重新 build 后仍偶发 alembic 异常，swagger 仍然不可用。

**排查过程**:

1. **检查 Docker 镜像层缓存**:  
   `docker history ruoyi-fastapi-backend-my:latest` 显示 `COPY . .` 层使用了旧缓存。

2. **对比宿主机与容器的 Python 版本**:  
   ```bash
   # 宿主机
   $ python3 --version
   Python 3.14.0
   
   # Docker 容器
   $ docker exec ruoyi-backend-my python --version
   Python 3.10.14
   ```

3. **发现致命问题**: 宿主机 `ruoyi-fastapi-backend/alembic/versions/__pycache__/` 下有大量 `*.cpython-314.pyc` 文件：
   ```
   0001_baseline_sys_ruoyi.cpython-314.pyc  (旧文件名，已被删的迁移)
   0002_baseline_biz.cpython-314.pyc        (旧文件名，已被删的迁移)
   0002_seed_all.cpython-314.pyc
   ```
   这些文件是**宿主机 Python 3.14 运行时代码时生成的字节码**。

4. **`.dockerignore` 已有 `__pycache__` 规则，但为何仍被 COPY?**  
   原因是 `.dockerignore` 只对 `COPY` 指令生效，宿主机文件系统仍保留这些文件。Docker build 的 cache 层可能之前已经注入了这些 pyc，除非用 `--no-cache` 或删除旧镜像。

5. **Docker 引擎缓存策略**:  
   ```bash
   # 即使改代码，如果上下层未变，Docker 会用旧缓存
   $ docker build --tag ruoyi-fastapi-backend .
   # 可能命中缓存，导致 COPY . . 层未更新
   ```

**修复**:
1. 手工清理宿主机 `alembic/versions/__pycache__/` 目录
2. 删除旧 Docker 镜像：`docker image rm ruoyi-backend-my:latest`
3. 执行 `./start-dev.sh --docker --rebuild`（`--rebuild` 参数强制 `--no-cache`）

### 2.3 阶段三：编写 `clean-cache.sh` 自动化清理脚本

**时间**: 07:34  
**动机**: 手动删除 `__pycache__` 不彻底，且容易遗漏其他缓存。

**实现**: `clean-cache.sh`

```bash
./clean-cache.sh              # 交互式清理
./clean-cache.sh --yes        # 跳过确认
./clean-cache.sh --logs       # 同时清理后端日志
./clean-cache.sh --dry-run    # 预览
```

**清理范围**:
- Python 缓存：`__pycache__/`、`*.pyc`、`*.pyo`
- macOS/测试缓存：`.DS_Store`、`.coverage`、`.pytest_cache/`、`.mypy_cache/`、`.ruff_cache/`
- 前端产物：`dist/`、`build/`、`.eslintcache`
- Python 元数据：`*.egg-info`、`*.egg`
- 日志：`backend.log`、`logs/2026/`（需加 `--logs`）

**保护范围（不会清理）**:
- `.git/`（仓库）
- `venv/`、`.venv/`（本地虚拟环境）
- `node_modules/`（依赖重装成本高）

**测试结果**:
```bash
$ ./clean-cache.sh --yes
完成：删除 13636 / 13636 个条目，释放 228691699 bytes (~218 MB)
```

## 3. 技术根因总结

### 3.1 Python 跨版本字节码兼容性

| 项目 | 宿主机 | 容器 |
|---|---|---|
| Python 版本 | 3.14 | 3.10 |
| pyc 格式 | `cpython-314` | `cpython-310` |

**Python 的 `.pyc` 文件包含版本戳（magic number）**，跨版本不兼容。宿主机 Python 3.14 生成的 `cpython-314.pyc` 放入镜像后，Python 3.10 的运行时无法识别，可能导致：
- `import` 失败或行为异常
- alembic 迁移检测到脏缓存，重新生成 migration
- swagger 路由注册异常

### 3.2 Docker 构建缓存陷阱

```
Dockerfile.my:
  COPY . .
  
# .dockerignore 排除 __pycache__，但如果：
# 1. 宿主机文件系统仍有这些文件
# 2. Docker daemon 缓存了包含这些文件的旧层
# 3. 没有使用 --no-cache 或 --rebuild
# → 旧 pyc 会持续污染新镜像
```

### 3.3 Vue Router 严格匹配

Vue Router 4 使用**严格路径匹配**（`strict` 模式默认开启），子路由路径拼接是精确的。`/system/role/user/3` 与任何已注册路由都不匹配，直接抛 `NavigationFailure`。
