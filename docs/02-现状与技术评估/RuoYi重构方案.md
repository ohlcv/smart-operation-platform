### B1. 7 级审批流后端

**来源**：`1/backend/app/api/v1/endpoints/contract.py`（323行）

**移植步骤**：

1. 在 `ruoyi-fastapi-backend/module_admin/` 下新建 `biz_contract/` 目录
2. 创建 `contract_controller.py`，移植 `submit / approve / reject / withdraw` 四个核心接口
3. 创建 `contract_service.py`，移植审批流逻辑
4. 移植 `enums.py` 中的 `Role`、`ApprovalAction`、`ContractStatus`、`ContractType` 枚举
5. 复用 `biz_contract` 和 `biz_approval` 表结构（见 C 类新建）

**关键适配点**：

| 适配项 | v1 原方式 | RuoYi 适配方式 |
|--------|-----------|----------------|
| 认证依赖 | `get_current_user(deps.py)` | RuoYi 的 `UserAuthDependency` |
| 响应格式 | `Response.ok(data)` | RuoYi 的 `parse_response` |
| 角色校验 | `require_roles()` | RuoYi 的 `RoleInterfaceAuthDependency` |
| 超级管理员 bypass | `if user.is_superuser` | 合并到 RuoYi 权限体系中 |

**审批链定义**（需新建枚举文件）：

```python
# 新建 custom_enums.py，区别于 RuoYi 框架层
class ApprovalRole(str, Enum):
    BUSINESS_HANDLER = "business_handler"      # 业务经办
    BUSINESS_REVIEWER = "business_reviewer"    # 业务复核
    RISK_AUDITOR = "risk_auditor"             # 风控审核
    FINANCE_HANDLER = "finance_handler"        # 财务经办
    FINANCE_REVIEWER = "finance_reviewer"      # 财务复核
    SCM_DIRECTOR = "scm_director"              # 供管公司负责人
    INVEST_DIRECTOR = "invest_director"          # 投资公司负责人

APPROVAL_CHAIN = [
    ApprovalRole.BUSINESS_HANDLER,   # Step 0: 自动完成（提交即审批）
    ApprovalRole.BUSINESS_REVIEWER,  # Step 1
    ApprovalRole.RISK_AUDITOR,       # Step 2
    ApprovalRole.FINANCE_HANDLER,    # Step 3
    ApprovalRole.FINANCE_REVIEWER,   # Step 4
    ApprovalRole.SCM_DIRECTOR,       # Step 5
    ApprovalRole.INVEST_DIRECTOR,    # Step 6: 终审
]
```

## 四、C 类：全新开发

> 策略：从头设计实现，需要架构设计、接口设计、数据库设计。
> 预估工作量：高，是本项目的核心工程量所在。

### C1. 审批流引擎（融合 RuoYi 权限体系）

**难度**：⭐⭐⭐⭐ 高

**核心矛盾**：RuoYi 原生无审批链概念；v1 Demo 有审批链但无菜单权限体系。需要融合两者。

**解决方案**：审批链角色（7 级）映射到 RuoYi 的 RBAC 角色表 `sys_role`，审批权限判断基于 `sys_user.role` 字段，不走 RuoYi 的菜单权限体系。

**设计要点**：

| 决策项 | 方案 |
|--------|------|
| 审批链角色存储 | 新建 `biz_approval_role` 表，或复用 `sys_role`，增加 `is_approval_role = True` 字段 |
| 审批角色与 RBAC 角色分离 | `sys_user.role` 存审批角色；`sys_user_role` 存 RBAC 角色（菜单权限） |
| 超管 bypass | `sys_user.is_superuser = True` 时跳过审批角色校验 |
| 审批记录存储 | `biz_approval` 表（见 B1） |

**新增数据库表**：

| 表名 | 说明 |
|------|------|
| `biz_contract` | 合同主表 |
| `biz_approval` | 审批记录表 |
| `biz_contract_attachment` | 合同附件表（可选） |

**接口设计**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/biz/contracts` | GET | 合同列表（按角色过滤可见范围） |
| `/biz/contracts` | POST | 创建合同（仅业务经办） |
| `/biz/contracts/{id}` | GET | 合同详情 |
| `/biz/contracts/{id}` | PUT | 编辑合同（仅草稿/驳回态） |
| `/biz/contracts/{id}` | DELETE | 删除合同（仅草稿/驳回态） |
| `/biz/contracts/{id}/submit` | POST | 提交审批 |
| `/biz/contracts/{id}/approve` | POST | 审批通过 |
| `/biz/contracts/{id}/reject` | POST | 审批驳回（必填原因） |
| `/biz/contracts/{id}/withdraw` | POST | 撤回（仅发起人） |
| `/biz/contracts/{id}/transfer` | POST | 转交（可选） |
| `/biz/contracts/{id}/cosign` | POST | 加签（可选） |
| `/biz/approvals/pending` | GET | 待我审批列表 |

**审批流状态机**：

```
draft ──提交──► pending ──审批通过──► approved
  │              │
  │              └──审批驳回──► rejected ──重新提交──► pending
  │
  └──删除──► (deleted)
```
